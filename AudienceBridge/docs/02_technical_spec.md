# Technical specification

## 1. Summary

AudienceBridge turns GA4 behaviour and CRM records into consented, hashed audiences for Google Ads Customer Match, prepares a paused campaign structure, and measures each audience with holdouts, a backtest and an A/A test. It runs as a SQL and Python pipeline on BigQuery Sandbox, scheduled by GitHub Actions.

**Functional**

## 3. Data audit

Real numbers (event counts, users, date range, unknown-value shares) are generated by `python -m audiencebridge audit` into `reports/data_audit.md`. Known properties of the source: the dataset covers 2020-11-01 to 2021-01-31, is obfuscated (some fields hold values such as `<Other>` or are null), and has no direct identifiers, so identity comes only from the synthetic CRM.

## 4. Opportunity sizing

The same audit report contains the per-segment sizes, revenue share and activatable counts. These are the numbers to quote to the client.

## 7. Segment definitions

Defined in `config/clients/gmerch_store.yaml`. As-of date 2020-12-31.

| Segment | Rule | Objective |
|---|---|---|
| `cart_abandoners_7d` | Added to cart in the last 7 days and did not purchase after | re-engage |
| `high_value_buyers` | Revenue at or above the 90th percentile among buyers | premium offers |
| `lapsed_buyers_30d` | Last purchase more than 30 days ago | win back |
| `apparel_browsers` | 3 or more apparel product views, no purchases | category prospecting |
| `high_propensity` | Propensity score at or above the 90th percentile | likely to buy |
| `recent_purchasers_exclusion` | Purchased in the last 14 days | exclude |

## 8. Privacy design

1. **Consent.** Only rows with both `consent_ad_user_data` and `consent_ad_personalization` true pass. Exclusions are counted by reason in `audience_summary` (no CRM match, no consent, no valid identifier).
2. **Normalisation.** Email: trim, lowercase, remove dots in the local part for gmail.com and googlemail.com, reject malformed. Phone: E.164, US numbers assumed when no country code. Names: trim, lowercase.
3. **Hashing.** SHA-256, hex encoded, in BigQuery.
4. **Boundary.** Plaintext lives only in `ab_raw`. `activation_ready` has hashes plus region and postal code (unhashed per API rules) and no user IDs.
5. **Access.** Grant `ab_raw` to the pipeline service account only; analysts and the Streamlit app read hashed and aggregate tables.
6. **Checks.** Automated: hashes are 64-char hex, no `@` or `+` in activation output, no non-consenting user's hash present, no holdout user present.

## 9. Activation design

- Customer Match goes through the Data Manager API (`audienceMembers:ingest`), because Google stopped accepting new Customer Match uploads through the Google Ads API.
- One request per up to 10,000 members; each member carries email, phone and, when complete, address identifiers; request-level consent is `CONSENT_GRANTED`.
- Modes: dry run (default; payloads validated, written, logged), `--live --validate-only`, `--live`.
- A segment is skipped if its activatable size is below `min_audience_size` or, in live mode, no user list ID is configured.
- Campaign mapping: one paused Search campaign, one ad group per non-exclusion segment, bids scaled by objective (cart abandoners highest), exclusion segments recorded as account-level exclusions. Created through the Google Ads API in a test account and read back with GAQL.
- Membership duration comes from `membership_days` per segment and is applied when the list is created.

## 10. Measurement design

- **Holdout.** `MOD(ABS(FARM_FINGERPRINT(user:segment:salt)), 100) < holdout_pct`. Deterministic. Exclusion segments are not held out.
- **Backtest.** Segments are defined on history up to the as-of date. Purchase rate and revenue per user in the following window are compared with the all-user baseline. Lift index is the ratio; significance is a two-proportion z-test against the rest of the population.
- **Model integrity.** `high_propensity` is evaluated only on users the model did not train on (`is_eval`), against the baseline on the same users.
- **A/A test.** No ads are served, so treated and holdout purchase rates must match. A Bonferroni-adjusted alpha across segments avoids flagging chance differences.
- **Success criteria.** Lift of at least 1.5x with p below 0.05 to recommend activation; A/A passing for all segments.
- **Limit.** This is a backtest. Incremental lift from ads needs a live flight against the holdout.

## 11. Alternatives considered

| Choice | Alternative | Decision |
|---|---|---|
| BigQuery pipeline | GA4 native audiences | GA4 audiences cannot use CRM identifiers, consent-by-record logic or custom measurement. Pipeline chosen. |
| Data Manager API for Customer Match | Google Ads API upload | The Ads API no longer accepts new Customer Match uploads. Ads API still used for campaigns. |
| SQL files run by Python | dbt Core | One fewer dependency for a small project; every table is already `CREATE OR REPLACE`, and Python adds config-driven rendering and tests. dbt is a reasonable swap at larger scale. |
| GitHub Actions | Cloud Scheduler / Run | The latter need billing. |
| Rule-based readout memo | Free-text generation | Every number in the memo comes straight from the result tables, so it cannot drift from the data. |

## 12. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Small audiences after CRM match | Funnel table shows each loss; minimum size gate; match rate is configurable |
| Class imbalance in the model | Class weighting in BigQuery ML, balanced weights in the fallback; evaluate on held-out users |
| API field changes | Payload builder isolated in one module; `--validate-only` before live |
| Sandbox limits and 60-day expiry | Full rebuild each run; small pre-aggregated tables for the dashboard |
| Leaked credentials | Git-ignored key files, repository secrets only |
| Spurious A/A failure | Bonferroni-adjusted alpha |

## 13. Rollout plan

1. Dry run: pipeline, payload review, data-quality checks.
2. Test account: create lists and the paused campaign structure; validate-only uploads.
3. Production (real client): replace the synthetic CRM source, confirm consent mapping with privacy, run a small flight with the holdout in place.
